# ADR-0002：Ymodem 文件发送的线程与状态模型

- 状态：Accepted
- 日期：2026-10-18
- 决策范围：M6 Ymodem 单文件发送

## 背景

原始 V1 范围明确排除了文件发送。用户随后要求加入 Ymodem 发送文件能力，并参考专业串口工具提供进度、取消和结果反馈。该需求改变了产品范围，但不应破坏既有分层、Worker 独占 Transport 和 UI 线程不阻塞的约束。

Ymodem 是严格的一问一答协议：发送文件头和数据块后必须等待接收端的 ACK/NAK/C，期间所有接收字节都属于协议状态机。若协议引擎与 Worker 的普通读取循环并存，ACK 会被当作 RX 数据，或文件帧与用户发送内容交错，导致传输失败。

## 候选方案

1. 在 Qt 主线程执行协议：实现简单，但等待接收端 `C` 和 ACK 会阻塞界面数十秒，违反 UI 线程不得阻塞的约束。
2. 为文件传输新建独立线程：需要把 `Transport` 所有权从 Worker 交接出去，并暂停普通读取循环；锁和生命周期复杂，且与 ADR-0001 的独占 Transport 模型冲突。
3. 在现有 `SerialWorker` 线程中同步运行协议引擎：复用独占 Transport，启动命令与普通写入共用 FIFO，传输期间由引擎消费全部串口字节。
4. 引入第三方 Ymodem 库：增加依赖、许可证和版本维护成本，协议逻辑本身规模可控。

## 决策

采用方案 3。

- `application/ymodem.py` 提供 `YmodemSender`，只依赖 `domain.Transport`、领域类型和注入的单调时钟。
- 文件发送命令与普通写入共用 Worker 的有界 FIFO 队列；命令入队前在锁内把传输标记为排队，之后的普通发送和 DTR/RTS 修改抛 `FileTransferError`。已排队的普通写入仍在文件头之前发送完成。
- 协议引擎在 Worker 线程内同步执行，独占读写；传输期间的协议字节不进入接收缓冲、自动日志和 RX/TX 计数。
- 不新增 `SessionState.TRANSFERRING`：传输是 `CONNECTED` 的子状态，通过 `SessionSnapshot.transfer` 表达，避免扩散到状态机、连接面板和关闭流程。
- 不新增 Qt 信号通道：进度与终态复用既有 `SessionSnapshot` → `QtSessionBridge` → queued signal 链路。
- 用户取消和 Worker 停止只设置取消事件；引擎在不超过 50 ms 的读切片或帧边界退出，尽力发送 8 个 CAN 字节。传输中关闭会话时，等待 Worker 退出的上限放宽为“当前 1K 帧写超时 × 2 + 0.5 s”（最多 5 s），覆盖无法中途打断的帧写入和随后的取消序列。
- 协议失败（超时、重试耗尽、对端取消、文件读取失败）保持串口连接；真实 `TransportIOError` 仍走既有致命错误和断开路径。
- 文件头固定 SOH/128 字节，数据块默认 STX/1024 字节并允许选择 SOH/128；CRC 使用标准库 `binascii.crc_hqx`，不新增运行依赖。
- 传输参数不写入 `AppConfig` schema；只作为运行时默认值和测试可注入选项。

## 后果

优点：

- 复用既有线程和 Transport 所有权，不引入新的并发边界。
- UI 线程不阻塞，取消和断开有有限响应时间。
- 协议字节不污染接收区、日志和统计。
- 无新增第三方依赖，协议引擎可脱离 Qt 和 pyserial 做确定性测试。

约束：

- 传输期间普通发送、周期发送和 DTR/RTS 修改必须被拒绝；UI 同时禁用对应控件。
- `write_all` 不能在帧中途打断，取消的实际线上响应受当前帧长度和波特率限制；低波特率应使用 128 字节块。在 1200 bps 及更低的极端链路上，关闭会话的 5 s 等待上限可能短于阻塞写超时，端口会在旧线程完成写超时后才释放，用户需稍后重试同一端口。
- 结束空块未确认时按成功处理，但可能留下接收端等待状态；这是为了兼容直接跳转应用的 bootloader。
- 文件名必须能转换为 ASCII 并放入 128 字节文件头，否则拒绝发送。
- 协议引擎运行期间 Worker 不处理新的控制命令，控制队列中的命令在传输结束后才生效。

## 验证

- 使用 Ymodem 接收端测试替身覆盖成功、NAK 重试、静默超时、EOT NAK、无最终 C、单/双 CAN、用户取消、空文件、序号回绕、CRC 和文件截断/过长文件名。
- 使用真实 `SerialWorker` 线程验证传输期间普通发送被拒绝、取消后连接可继续使用、协议失败不停止 Worker。
- 使用 `SessionController` 验证快照进度、系统记录、断开取消和终态兜底。
- 使用离屏 Qt 测试验证面板按钮、进度、取消和失败文案。
- 真实设备和 bootloader 的兼容性仍需按发布清单在目标硬件上验收。
