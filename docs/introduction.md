# SerialMNT 项目介绍与使用指南

> 文档版本：1.0  
> 软件版本：0.7.2  
> 更新时间：2026-10-18  
> 适用读者：部门内嵌入式开发、硬件调试与测试同事  
> 项目地址：<https://github.com/MengYang-x/SerialMNT>

SerialMNT 是一款面向嵌入式开发、硬件调试和测试场景的跨平台串口调试助手。它把多设备并行调试、文本与 HEX 收发、终端仿真、日志留档和 Ymodem 固件传输整合在同一个桌面程序里，Windows 和 Linux 使用同一套交互方式。

当前版本 **0.7.2**，Windows 单文件约 46 MB，目标机器无需安装 Python。

## 1. 为什么推荐它

日常调试通常要在多个工具之间切换：一个串口助手看日志，一个终端敲命令，再找一个工具传固件，最后手动复制日志留证。SerialMNT 针对这些重复动作做了整合：

- **多标签并行**：一个窗口同时连接多块板卡，每个标签独立配置、独立日志、独立视图。
- **看得懂设备输出**：文本、HEX、终端三种显示方式随时切换，支持 ANSI 颜色、光标移动、退格和清屏。
- **快速定位问题**：时间戳、行号、关键字高亮、日志级别着色、`Ctrl+F` 循环查找。
- **数据可追溯**：连接即自动写日志，CSV 同时保留文本和原始 HEX，可随时导出。
- **固件升级不换工具**：内置 Ymodem 单文件发送，带进度、速度和取消。
- **长时间运行可控**：内存缓冲有明确上限，端口异常和日志写入失败不会拖垮整个程序。

## 2. 核心功能与亮点

### 2.1 一个窗口，多台设备并行调试

每个标签对应一条独立串口连接，拥有自己的端口参数、接收缓冲、自动日志和显示偏好。调试主控与从机、同时观察多块板卡时，不需要反复关闭再打开窗口。

- 标签可拖动排序，双击或右键可重命名，名称随配置保存。
- 同一进程内不允许两个会话占用同一端口，避免误操作。
- 重启后恢复上次的标签和参数，但**不会自动连接或占用端口**。
- 新建或切换标签时有轻量滑动过渡，不改变任何收发内容；快速连续切换不会叠加动画。

### 2.2 文本、HEX、终端三种查看方式

接收区顶部可随时切换“文本/HEX”，切换只影响显示，不改变原始字节、内存缓冲和日志。设备输出二进制数据时，用 HEX 模式即可核对真实内容。

“终端/分栏”按钮可进入终端视图，按终端语义渲染设备输出：

- 支持 CR 行覆盖、退格、换行、ANSI 16 色与 256 色、光标移动和清屏。
- 光标跟随设备输出位置，可直接在 `#` 或 `$` 提示符后输入并按回车发送。
- 支持 `↑` / `↓` 召回发送历史，多行粘贴按非空行依次发送。
- 终端滚动历史上限 5000 行，界面只渲染最近 2000 行，长时间输出不会拖慢界面。

### 2.3 为“找问题”设计的显示能力

- **时间戳**：精确到毫秒，快速判断事件间隔。
- **行号**：按显示行从 1 编号，方便和日志、截图、同事口头描述对齐。
- **日志级别着色**：`Error` 红色、`Warning` 黄色、`Pass` 绿色、`Debug` 蓝色、`Info` 默认色；整词匹配，不区分大小写，一行命中多个级别时按优先级取最高。字段和颜色可在“日志级别颜色…”中自定义。
- **终端高亮**：终端视图自动标出 IPv4/MAC、URL、邮箱，以及 `OK`、`SUCCESS`、`PASS`、`ERROR`、`FAIL`、`WARN` 等关键字，可用“高亮”勾选框整体关闭。
- **查找**：`Ctrl+F` 输入关键词，`Enter` / `Shift+Enter` 在命中项之间循环跳转，右侧显示“当前/总数”。
- **自动换行、暂停、清屏**：都只影响界面显示，串口读取、内存缓冲和自动日志照常运行。

### 2.4 面向长时间运行的可靠性

- 内存缓冲上限为 **100,000 条记录或 32 MiB**，超过任一限制优先淘汰最旧记录，不会无限增长。
- 界面只渲染最近 2000 条，更早内容仍保留在缓冲和导出文件中，顶部会提示隐藏条数。
- 端口不存在、被占用、无权限或设备拔出时，界面给出分类错误，主程序不崩溃。
- 日志写入失败会提示，但不会主动断开串口。
- 配置采用临时文件原子替换，保留 `.bak`；文件损坏时另存为 `settings.corrupt.<时间>.json` 后按无配置启动，不会卡在启动阶段。
- 自动滚动只在视图位于底部时跟随新记录；手动滚上去查看历史后，点击接收区或继续收数据都不会被强行拉回底部（0.7.2 修复）。

### 2.5 自动日志与可追溯的数据

启用“自动保存”后，每次成功连接都会新建一个日志文件，断开时刷新关闭。默认目录是用户目录下的 `Documents/SerialMNT/Logs`，也可以自行选择。

- 格式可选 `CSV` 或 `TXT`，该格式同时用于自动日志和“导出当前缓冲”。
- CSV 使用 UTF-8 BOM，字段固定为 `timestamp,direction,encoding,text,hex`。其中 `hex` 保留原始字节，文本乱码时仍能还原真实数据。
- TXT 每行格式为 `[本地时间] 方向 [编码] 文本`。
- 文件名会清理端口名中的非法字符，重名时追加序号。
- 清屏只清空内存显示，不删除已写入的自动日志。

### 2.6 提升日常发送效率

- 发送历史最多保留 100 条，连续重复内容自动合并；历史只回填编辑器，不会误发送。
- 换行策略支持无换行、`CR`、`LF`、`CRLF`，文本和 HEX 发送共用；新会话默认 `LF`。
- 周期发送间隔支持 `10 ms` 到 `86,400,000 ms`（24 小时），默认 `1000 ms`；断开或关闭标签时自动停止。
- 文本发送支持 `UTF-8`、`GB18030`、`ASCII`；HEX 模式接受 `AA 01 FF` 或 `AA01FF`，奇数长度和非法字符会被拦截。
- `Ctrl+Enter` 直接发送，发送编辑器自动增高，最多显示 5 行。

### 2.7 内置 Ymodem 固件传输

连接串口后即可在左侧“Ymodem 发送”分组选择文件并发送，无需另装传输工具。

- 默认 1K 块（1024 字节），接收端只支持 128 字节块时可取消勾选。
- 显示块号、百分比、速度和重试次数；支持安全取消。
- 要求 8 数据位、无校验，且不要启用 XON/XOFF 流控；不满足时会拒绝发送并提示调整参数。
- 协议帧不会混入接收区和日志，只追加“开始发送文件”“发送完成/失败/已取消”等系统记录。
- 传输失败不会断开串口，修正后可以重新发送。

### 2.8 界面与跨平台体验

- 主题支持“跟随系统”“浅色”“深色”，切换后立即重绘，无需重开标签。
- 字号支持 9–24 点，`Ctrl+=` / `Ctrl+-` / `Ctrl+0` 快速缩放，设置立即作用于所有标签并随配置保存。
- 下拉框不响应鼠标滚轮，滚动侧栏时不会误改端口、波特率等关键参数。
- 底部状态条用圆点颜色区分已连接、未连接和错误，并实时显示 RX/TX 字节数。
- Windows 10/11 x64 与 Ubuntu 22.04 及以上 Linux x64 使用同一套功能。
- 启动约 3 秒后后台检查 GitHub Releases；只在发现新版本时提示并打开下载页，**不自动下载、不自动安装、不上传任何设备或串口数据**。

### 2.9 工程质量（面向研发同事）

- 采用 `domain` / `application` / `infrastructure` / `ui` / `bootstrap` 分层，依赖方向明确，串口 I/O 不进入 UI 线程。
- 每条串口会话对应一个独立 Worker 线程和独占 Transport，命令与事件通过队列传递。
- 串口、时钟、配置路径和文件系统均可注入，测试使用 Fake Transport 和 Fake Clock，不依赖固定 `sleep`。
- 0.7.2 发布记录：**628 项自动化测试通过，语句覆盖率 89.89%**；GitHub Actions 执行文档同步、版本同步、Ruff 和 pytest。
- 项目代码采用 MIT 许可证，第三方依赖及许可证见 `THIRD_PARTY_NOTICES.md`。

## 4. 快速上手（约 5 分钟）

### 4.1 获取并启动

Windows 用户从 GitHub Releases 下载 `SerialMNT.exe`，双击即可运行。下载后可核对校验值：

```powershell
certutil -hashfile SerialMNT.exe SHA256
```

Linux 用户下载对应单文件后执行：

```bash
chmod +x SerialMNT
./SerialMNT
```

Linux 单文件仍依赖图形与系统库；如果启动时报 Qt `xcb` 平台插件错误，需先安装当前发行版对应的 XCB 运行库。

也可以从源码运行（需要 Python 3.10.x）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m serialmnt
```

首次从源码安装依赖较慢时，可在 `pip install` 后追加国内镜像参数 `-i https://mirrors.aliyun.com/pypi/simple/`。

### 4.2 连接设备

1. 按 `Ctrl+T` 新建会话，或点击标签栏的“+”。
2. 在左侧“串口设置”选择端口。列表显示“端口名 · 设备描述”，未连接时每 30 秒自动刷新，也可点 ⟳ 立即重新枚举。
3. 设置波特率（默认 `115200`）和校验位、停止位、流控；数据位固定为 `8`。
4. 按设备需要选择编码，默认 `UTF-8`；中文设备可切换 `GB18030`。编码修改后需断开重连才生效。
5. 需要时勾选 DTR/RTS。它们每次启动默认关闭，连接期间也可以直接切换。
6. 点击蓝色“连接”按钮。成功后按钮变为红色“断开”，底部状态条显示绿色圆点和实际端口。

连接参数在连接期间锁定，修改后必须断开再连接。端口被占用、无权限或不存在时，界面会给出具体提示，不会影响其他标签。

### 4.3 发送第一条命令

1. 在右下发送编辑器输入命令，例如 `help`。
2. 选择换行方式。新会话默认 `LF`，多数 MCU 命令行可直接使用；需要 `CRLF` 时手动切换。
3. 按 `Ctrl+Enter` 或点击“发送”。

接收区会同时显示 `RX` 和 `TX`，并带上时间戳、方向前缀和可选行号。文本乱码时可切到 HEX 核对原始字节。

### 4.4 留下日志

1. 在左侧“日志与导出”中勾选“自动保存”。
2. 选择 `CSV` 或 `TXT`，确认日志目录。
3. 重新连接后，程序会自动创建 `SerialMNT_端口名_YYYYMMDD_HHMMSS.扩展名`。
4. 需要单独保存当前内容时，点“导出当前缓冲”，选择目标路径即可。

自动日志设置只能在未连接时修改，修改后对下一次连接生效。

## 5. 使用详解

### 5.1 主界面

主窗口顶部是会话标签栏，右侧依次为“主题”“字号”和“☰”菜单。每个标签内部：

- **左侧设置面板**：串口设置、Ymodem 发送、日志与导出。可通过接收标题行最左侧的按钮收起。
- **右上接收区**：格式切换、暂停、清屏、终端/分栏切换，以及时间戳、行号、自动滚动、自动换行等显示选项。
- **右下发送区**：格式、换行、发送按钮、历史下拉框和周期间隔。
- **底部状态条**：连接状态、端口、RX/TX 累计字节数。

窗口最小尺寸为 900×600；窗口变矮时设置面板内部可滚动。

### 5.2 串口设置

| 选项 | 可选值 | 说明 |
|---|---|---|
| 端口 | 枚举或手动输入 | 显示设备描述，支持热插拔刷新 |
| 波特率 | 正整数 | 默认 `115200` |
| 数据位 | 固定 `8` | 下拉框不提供其他值 |
| 校验位 | 无、偶、奇、标记、空格 | 对应 `N/E/O/M/S` |
| 停止位 | `1`、`1.5`、`2` | 按设备要求选择 |
| 流控 | 无、XON/XOFF、RTS/CTS、DSR/DTR | Ymodem 不要使用 XON/XOFF |
| 编码 | UTF-8、GB18030、ASCII | 收发共用，修改后需重连 |
| DTR/RTS | 勾选 | 连接期间可实时切换 |

### 5.3 接收区操作

| 控件/操作 | 作用 |
|---|---|
| 文本/HEX | 切换显示格式，不改变原始字节和日志 |
| 时间戳 | 显示本地时间，精确到毫秒 |
| 行号 | 按显示行编号，默认开启，不写入日志 |
| 自动滚动 | 仅在视图位于底部时跟随；滚离底部自动暂停 |
| 自动换行 | 默认开启；关闭后长行横向滚动 |
| 暂停 | 暂停界面追加和重绘，读取、缓冲、日志继续 |
| 清屏 | 确认后清空当前内存缓冲，不删除自动日志 |
| 终端/分栏 | 切换终端语义视图与常规分栏视图 |
| 高亮 | 终端视图内整体开关 IP/MAC/URL/邮箱/关键字标记 |
| 查找 | `Ctrl+F` 打开，循环跳转，`Esc` 关闭 |

接收内容不可编辑，但可以选中复制或右键“复制/全选”。

### 5.4 终端视图

终端视图适合持续观察设备输出并快速交互：

- 设备输出 `#` 后，光标停在 `#` 后，直接键入命令并按回车发送。
- `↑` / `↓` 召回发送历史；多行粘贴会按非空行依次发送。
- 顶部“发送设置”可切换文本/HEX、换行方式和最近历史。
- 终端视图不显示发送区、时间戳和行号；周期发送请在分栏视图使用。
- 支持 16 色与 256 色 ANSI，不支持真彩和 alternate screen。

### 5.5 发送区

- **文本模式**：按当前会话编码转换后发送。空输入且选择“无换行”时不发送；选择 `CR`/`LF`/`CRLF` 时发送对应换行字节。
- **HEX 模式**：接受连续或空格分隔的十六进制，例如 `AA 01 FF`、`AA01FF`。奇数长度或非法字符会阻止发送。
- **发送历史**：成功发送的非空内容进入历史，最多 100 条；连续重复内容合并。
- **周期发送**：设置间隔后点击周期按钮；只有已连接且编辑器非空时才能启动，断开、关闭标签或退出时自动停止。

### 5.6 用 Ymodem 发送文件

1. 连接串口，确认参数为 8 数据位、无校验，且未启用 XON/XOFF。
2. 在左侧“Ymodem 发送”点击“…”选择文件，确认文件大小。
3. 默认使用 1K 块；接收端只支持 128 字节块时取消勾选。
4. 让设备进入 Ymodem 接收模式（部分设备需复位或按住升级键）。
5. 点击“发送文件”，等待接收端发送 `C`，程序随后发送文件名和大小并逐块传输。
6. 观察块号、百分比、速度和重试次数；需要中止时点“取消”。

传输期间手动发送和周期发送会暂停，协议帧不会显示在接收区。传输失败不会断开串口，可以修正后重发；断开连接、关闭标签或退出程序会中止传输。

### 5.7 日志格式

CSV 字段固定如下，新增字段不会改变现有语义：

| 字段 | 含义 |
|---|---|
| `timestamp` | 本地时间，毫秒精度并带时区偏移 |
| `direction` | `RX`、`TX` 或 `SYSTEM` |
| `encoding` | 记录使用的文本编码 |
| `text` | 按指定编码解码的文本 |
| `hex` | 原始字节的大写 HEX 文本 |

TXT 每行格式：

```text
[本地时间] 方向 [编码] 文本
```

文本无法表示原始字节时，CSV 的 `hex` 字段或 HEX 显示模式仍可用于核对。

### 5.8 配置、主题与恢复

- Windows 配置路径：`%APPDATA%\SerialMNT\settings.json`
- Linux 配置路径：`${XDG_CONFIG_HOME:-$HOME/.config}/SerialMNT/settings.json`
- 保存内容：主题、窗口布局、活动标签、串口参数、显示偏好、日志偏好、发送格式、换行、周期间隔、发送历史和视图模式。
- 配置变更延迟约 500 ms 合并写入，退出时立即刷新；写入采用临时文件替换并保留 `.bak`。
- 配置损坏时会另存为 `settings.corrupt.<UTC时间>.json`，随后按无配置状态启动。
- 启动恢复只还原参数，不会自动连接串口。

## 6. 典型使用场景

### 6.1 抓取设备启动日志

1. 新建会话，按设备参数连接，启用自动日志（CSV）。
2. 进入终端视图，保持自动滚动在底部。
3. 复位设备，观察带时间戳的启动输出；用 `Ctrl+F` 搜索 `ERROR`、`FAIL` 或关键字。
4. 需要提交问题时，“导出当前缓冲”生成完整文件，CSV 中的 `hex` 可还原原始字节。

### 6.2 交互式命令行调试

1. 连接后切到终端视图，光标会跟随设备提示符。
2. 直接输入命令并回车；用 `↑` / `↓` 召回历史命令。
3. 需要重复下发时切回分栏视图，使用历史下拉框或周期发送。
4. 开启日志级别着色，异常行会整行标红或标黄。

### 6.3 周期压测与长时间观察

1. 在发送区填入测试命令，设置周期间隔（例如 1000 ms）。
2. 启动周期发送，保持自动日志开启。
3. 用其他标签同时观察设备其他串口或执行其他任务。
4. 长时间运行后，内存缓冲按 100,000 条 / 32 MiB 上限淘汰旧记录，界面始终只渲染最近 2000 条，不会因数据量增长卡死。

### 6.4 通过 Ymodem 升级固件

1. 以 8N1、无 XON/XOFF 连接设备。
2. 选择固件文件，按 bootloader 要求选择 1K 或 128 字节块。
3. 让设备进入接收模式，点击“发送文件”。
4. 观察进度和重试次数；失败可保留连接并重试，必要时点“取消”安全中止。

### 6.5 现场问题留证

1. 连接前设置好日志目录和 CSV 格式。
2. 复现问题时保留自动日志，不要清屏或关闭标签。
3. 断开后日志自动刷新落盘；把 CSV 和问题时间点一起提交，`timestamp`、`direction` 和 `hex` 能还原完整收发过程。

## 7. 常见问题速查

| 现象 | 处理方式 |
|---|---|
| 端口列表为空 | 检查驱动和设备管理器；点 ⟳ 重新枚举；Linux 确认 `/dev/ttyUSB*` 或 `/dev/ttyACM*` |
| 提示端口被占用 | 关闭其他串口工具，检查本应用其他标签是否已连接同一端口 |
| Linux 提示权限不足 | 将用户加入 `dialout` 等串口用户组并重新登录，不要长期 `chmod 777` |
| 中文乱码 | 切换 `GB18030` 或 `ASCII` 后断开重连；或切到 HEX 核对原始字节 |
| 日志文件未生成 | 确认自动保存已启用、目录可写、磁盘空间充足；自动日志只在新连接后创建 |
| 配置被重置 | 检查配置目录中的 `settings.corrupt.*.json`，可从 `.bak` 恢复 |
| 检查更新失败 | 确认能访问 `api.github.com`；离线环境下该检查静默失败，不影响串口功能 |

更多细节见 `docs/user-guide.md`，或按 `F1` 打开程序内置手册。

## 8. 已知限制

- 仅支持 Ymodem 单文件**发送**，不支持接收、批量/目录传输、断点续传，也不支持 XMODEM、ZMODEM。
- 不支持日志回放、脚本、Modbus、协议插件、实时波形和数据分析。
- 不提供自动下载或自动替换式更新；更新检查只提示新版本并打开下载页。
- 不提供遥测、崩溃上报和代码签名。
- 暂停按钮只暂停界面显示，不会暂停串口读取、缓冲和日志。
- 终端仿真支持 16 色与 256 色，不支持真彩、alternate screen、滚动区域和 OSC 标题。
- Windows 和 Linux 单文件必须分别在对应操作系统上构建，不能交叉生成。
- 长时间稳定性、拔插和真实硬件矩阵仍需按发布清单在目标机器验收。

## 附录 A 技术架构速览

```text
bootstrap -> ui -> application -> domain
     |           |            |
     +---------->+------------+-> infrastructure implements domain ports
```

- **domain**：不可变模型、状态机、编解码、缓冲、错误和外部能力协议，只依赖标准库。
- **application**：会话编排、Worker 命令队列、日志协调和更新服务，不依赖 PySide6。
- **infrastructure**：pyserial Transport、端口扫描、JSON 配置、CSV/TXT 日志和系统时钟。
- **ui**：PySide6 界面，只通过应用层命令和只读快照工作。
- **bootstrap**：唯一的具体实现组装点。

线程模型：每个已连接会话对应一个独立 Worker 线程和独占 Transport；UI 线程只处理界面，不执行阻塞串口 I/O；Worker 向 UI 发送不可变事件或快照，不跨线程共享可变模型。

数据权威性：原始字节是唯一权威数据，文本和 HEX 都是显示派生值；切换显示模式、查找和暂停都不会修改原始字节或日志。
