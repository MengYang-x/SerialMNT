# SerialMNT 使用手册

> 文档版本：1.0  
> 软件版本：0.4.0  
> 对应基线提交：`cb6c23a`  
> 更新时间：2026-10-18  
> 适用平台：Windows 10/11 x64、Ubuntu 22.04 及兼容 Linux x64

## 1. 安装与启动

### 1.1 从源码运行

先按 `README.md` 创建 `.venv` 并安装开发依赖。

Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe -m serialmnt
```

Linux：

```bash
./.venv/bin/python -m serialmnt
```

### 1.2 运行单文件版本

Windows：

```powershell
.\dist\SerialMNT.exe
```

Linux：

```bash
chmod +x ./dist/SerialMNT
./dist/SerialMNT
```

Linux 单文件仍依赖图形和系统库。如果启动时报 Qt `xcb` 平台插件错误，应先安装当前发行版对应的 XCB 运行库。单文件首次启动会解压到系统临时目录，因此启动速度可能慢于源码运行。

## 2. 主窗口

主窗口顶部只有一行标签栏，没有单独的菜单栏和工具栏。界面采用统一的现代扁平外观：浅灰窗口底色配白色卡片式分组框、圆角控件和细分隔线；“连接”“发送”等主操作使用蓝色实心按钮，其中“连接”按钮在连上串口后转为红色以区分连接状态，悬停、按下与禁用态有明确区分；浅色和深色共用同一套设计令牌，配色与圆角保持一致。

- 窗口与任务栏使用应用图标（蓝色渐变底配白色双向箭头）；Windows 单文件产物会把同一图标写入可执行文件。

- 标签栏左侧是会话标签，“+”新建按钮紧跟最后一个会话标签的右边，新增或关闭会话时一起移动；标签栏右端依次是“主题”下拉框、“字号”下拉框和“☰”菜单。标签多到放不下时“+”会隐藏，此时用 `Ctrl+T` 或 ☰ 菜单新建会话。
- “字号”下拉框控制接收区和发送编辑器的字体大小（含终端视图），默认“跟随系统”，可选 `9` 到 `24` 的点数；改动立即作用于所有标签页，并随全局配置保存，重启后恢复。在接收区或发送编辑区上按住 `Ctrl` 滚动滚轮可以快速缩放，也可以用 `Ctrl+=`（或 `Ctrl++`）放大、`Ctrl+-` 缩小、`Ctrl+0` 恢复默认；☰ 菜单里的“字号”子菜单提供相同操作。
- “主题”下拉框可切换“跟随系统”“浅色”“深色”；切换后立即用新配色重绘接收区并刷新状态条圆点，无需重开标签。
- 所有下拉选择框只在点击展开、输入或使用键盘时改变取值，鼠标滚轮停在上面不会误改选项；滚轮会继续用于滚动侧栏或页面。
- 接收标题行的“自动换行”勾选框默认开启，超长行按接收区宽度折行显示；关闭后长行改为横向滚动。该设置对分栏和终端视图都生效，并随标签保存。
- “+”与“☰”菜单里的“新建会话”等价，快捷键为 `Ctrl+T`；`☰` 菜单还包含“关闭当前会话”和“退出”。
- `☰` 菜单的“使用帮助”（快捷键 `F1`）打开内置使用手册窗口：左侧是章节目录，右侧是完整手册正文，可边看帮助边继续操作；窗口非模态，重复打开只会前置已有窗口。
- `☰` 菜单的“检查更新”会立即查询 GitHub Releases；检查期间状态栏显示“正在检查更新…”，完成后显示“当前已是最新版本”或检查失败提示。
- 每个标签页分为左侧设置面板和右侧收发区，右侧上半部分是“接收”，下半部分是“发送”。
- “接收”标题行右侧的“终端/分栏”切换按钮可进入终端视图：接收文本按终端语义渲染，支持 CR 行覆盖、退格、换行、ANSI 颜色、光标移动和清屏，不添加应用自己的提示符；设备输出 `#` 后光标就在 `#` 后，直接输入并按回车发送。终端模式没有独立发送行或发送按钮，每个标签独立保存该切换。接收文本中的 IPv4/MAC、URL、邮箱，以及整词匹配的关键字（OK/SUCCESS/PASS 绿、ERROR/FAIL 红、WARN 黄，大小写不敏感）会用主题高亮色标出，设备已用 ANSI 设色的字符保持原色；终端标题行的“高亮”勾选框可整体关闭这些标记（默认开启，随标签保存）。
- 设置面板折叠按钮位于“接收”标题行最左侧；收起后只保留收发区。
- 接收标题行放不下所有控件时（例如窗口缩到最小尺寸），会按“自动滚动 → 自动换行 → 高亮 → TX → RX → 时间戳 → 清屏 → 暂停”的顺序把次要控件收进标题行最右端的“⋯”菜单；标题、格式、暂停/清屏、终端/分栏和“⋯”本身始终留在行内，窗口变宽后自动还原，勾选状态不会丢失。
- 接收区没有可显示内容时显示一行灰色“暂无数据”提示，收到数据后自动消失；该提示不属于缓冲区内容，不写入日志也不影响导出。
- 底部状态条显示状态、端口和 RX/TX 字节数，并用圆点颜色区分状态：绿色为已连接、黄色为未连接（含已关闭）或连接中/断开中、红色为错误。
- 未连接时状态条上的端口跟随端口输入框内容实时更新，并带上设备描述（例如 `COM5 (USB-Enhanced-SERIAL CH343)`）；连接后显示实际使用的端口。
- 标签可以拖动排序，用标签上的关闭按钮或 `Ctrl+W` 关闭当前标签。
- 双击标签或右键标签选“重命名…”可以自定义会话名称；名称会随配置保存，重启后按新名称恢复，最长 40 个字符，留空或超长会提示错误。
- 窗口最小尺寸为 900×600；窗口变矮时设置面板内部可用滚动条访问完整内容。

程序每次启动约 3 秒后会在后台检查一次新版本：没有新版本或网络不可用时保持静默，不打断当前操作；发现新版本时弹窗显示当前版本和最新版本，更新说明可在弹窗详情中展开，点“前往下载”用系统浏览器打开 GitHub Release 页面，点“稍后”关闭。程序不会自动下载或执行任何文件，也不会发送设备信息、串口数据或配置。检查更新需要访问 `api.github.com`，离线环境可忽略其静默失败。

常用命令：

| 操作 | 快捷键 |
|---|---|
| 新建会话 | `Ctrl+T` |
| 关闭当前会话 | `Ctrl+W` |
| 退出程序 | `Ctrl+Q` |
| 发送当前内容 | `Ctrl+Enter` |
| 查找接收内容 | `Ctrl+F` |
| 使用帮助 | `F1` |

窗口大小、活动标签、主题、侧栏状态、分隔比例、各标签视图模式和其余偏好会在关闭后保存。下次启动恢复窗口尺寸、标签和参数，窗口位置统一居中显示在主屏可用区域；上次为最大化或全屏时保持该状态，但不会自动连接串口。

## 3. 串口设置与连接

每个标签使用独立的串口连接。左侧“串口设置”面板包含端口、波特率、数据位、校验位、停止位、流控、编码、DTR/RTS 和连接按钮。

- 端口列表在未连接时每 30 秒自动刷新一次；也可以点端口框右侧的 ⟳ 按钮立即重新枚举，端口组合框还可以手动输入设备名。
- 列表项会显示「设备名 · 设备描述」（例如 `COM5 · USB-Enhanced-SERIAL CH343`），便于分辨是哪个设备；端口框本身只显示端口名，描述过长时把鼠标停在端口框上可看完整内容。
- 默认波特率为 `115200`，也可输入其他正整数。
- 数据位支持 `5`、`6`、`7`、`8`。
- 校验位支持无校验、偶校验、奇校验、标记和空格。
- 停止位支持 `1`、`1.5`、`2`。
- 流控支持无流控、XON/XOFF、RTS/CTS、DSR/DTR。
- 编码支持 `UTF-8`、`GB18030`、`ASCII`，默认 `UTF-8`；它同时用于接收解码和发送编码，修改后需断开并重新连接才生效，已缓冲的旧记录仍按接收时的编码显示。
- 未连接时修改参数只更新当前标签配置；连接后连接参数会锁定，必须先断开才能再次修改。
- DTR 和 RTS 每次启动都从关闭开始，不恢复上次退出时的状态；连接期间可以直接切换并立即发送到设备。
- 连接成功后按钮变为红色“断开”，与未连接时的蓝色“连接”一眼区分；点击后程序等待工作线程完成读取、日志刷新和串口关闭。
- 连接和断开通常在几十毫秒内完成，此时按钮直接切到结果文案，不会闪现“正在连接”“正在断开”；只有耗时超过 200 毫秒时才显示等待文案。

同一进程内不允许两个会话同时占用相同端口。端口不存在、被其他程序占用或当前用户无权限时，界面会显示错误提示，原会话不会导致主程序崩溃。

## 4. 接收显示

接收标题行提供以下控制，左侧是显示与过滤，右侧是操作；窗口较窄时部分控件会收进最右端的“⋯”菜单，菜单项与行内控件状态保持同步。

- “文本/HEX”下拉框：在文本和 HEX 显示之间切换。切换只改变界面渲染，不改变原始字节或自动日志。
- “时间戳”：显示或隐藏本地时间，精确到毫秒。
- `RX` / `TX`：控制接收方向和发送方向记录是否显示。
- “暂停”：暂停界面追加和重新渲染；串口读取、内存缓冲和自动日志继续运行。
- “清屏”：确认后清空当前标签的内存缓冲，不删除已经写入的自动日志。
- “自动滚动”：控制新记录到达时是否滚动到底部。
- “⋯”：收纳放不下的次要开关；勾选项在菜单里同样显示勾选状态，点击效果与行内勾选框一致。

接收内容使用等宽字体，便于对齐 HEX 字节和日志列。分栏视图下可拖动分隔条调整接收区与发送区的高度比例；终端视图按终端语义渲染 RX 文本，输入草稿跟随设备光标，适合持续查看设备输出并快速输入。两个视图的接收内容都不可编辑：可以选中、按 Ctrl+C 复制或用右键菜单“复制/全选”，但不能剪切、删除或粘贴修改；终端视图右键只有“复制”和“全选”。存在选中内容时自动滚动会暂停、新收到数据不会清空选中；点掉选中后自动恢复滚动。

焦点在接收区时按 `Ctrl+F` 打开查找栏：输入关键词后按 `Enter` 跳到下一个匹配，`Shift+Enter` 跳到上一个，到达首尾后循环；右侧显示“当前/总数”或“无匹配”。查找不区分大小写，命中项用选区标出并滚动到可见位置，按 `Esc` 或“×”关闭并把焦点还给接收区。查找范围是接收区当前已渲染的文本，因此受 `RX`/`TX` 过滤、文本/HEX 显示模式和最近 `2000` 条渲染上限影响；查找不会修改内存缓冲、原始字节或日志，分栏和终端视图都可使用。

文本编码在“串口设置”的“编码”下拉框中选择，默认 `UTF-8`；若设备使用其他编码，可切到 `GB18030` 或 `ASCII`，也可以先用 HEX 模式核对原始字节。接收和发送按方向区分颜色：时间戳用灰色弱化，`RX`/`TX` 前缀使用方向色并加粗（浅色主题为绿色 RX、蓝色 TX，深色主题使用对应亮色），数据正文统一使用主题的高对比文本色，HEX 模式同样适用；`SYSTEM` 行整行使用灰色。深色主题的占位提示和禁用文字经过单独调校，避免与正常文字混淆。

内存缓冲最多保留 `100,000` 条记录或 `32 MiB` 原始数据，超过任一限制时优先淘汰最旧记录。清屏只清空当前内存内容，不重置进程累计的 RX/TX 字节统计。

界面只渲染最近 `2000` 条记录，更早的内容仍保留在内存缓冲和导出文件中；接收区顶部会用一行“…”提示说明被隐藏的记录数。切换显示模式、时间戳或方向过滤只重绘这段窗口，因此大缓冲下操作依然流畅。

## 5. 发送数据

分栏视图下，发送标题行分成两行：第一行是“格式”“换行”和“发送”按钮，第二行是“历史”、周期间隔和周期按钮。发送编辑器同样使用等宽字体，HEX 模式下便于核对字节；它默认只占一行高，随输入内容自动长高，最多显示 5 行，再多则改为编辑器内部滚动，省下的高度留给接收区。终端视图不显示发送区，也不显示时间戳、RX/TX 过滤和日志前缀，直接在接收流末尾输入并按回车发送；按 ↑/↓ 召回发送历史，多行粘贴会按非空行依次发送。终端顶部“发送设置”菜单可切换文本/HEX、换行和最近历史，周期发送只在分栏视图使用。发送成功后本地草稿立即移除，命令是否留在画面中取决于设备回显。新建会话默认选择 LF；空输入按回车时，“无换行”不发送，CR/LF/CRLF 发送对应换行字节，不会弹出空数据错误。

### 5.1 文本发送

文本模式把编辑器内容按当前会话文本编码转换为字节，默认编码为 `UTF-8`。编辑器为空时提交不会调用空 bytes 发送：无换行时无操作，配置 CR/LF/CRLF 时发送对应换行字节；空内容不会加入历史。

### 5.2 HEX 发送

HEX 模式接受连续十六进制字符或带空白分隔的字节，例如：

```text
AA 01 FF
```

也可以写成：

```text
AA01FF
```

HEX 数据必须由完整字节组成；奇数长度或包含非法字符时会阻止发送并显示错误。显示和日志中的 HEX 统一使用大写、空格分隔格式。

### 5.3 换行策略

发送时可以选择：

- “无换行”：不追加任何字节。
- `CR`：追加 `0D`。
- `LF`：追加 `0A`。
- `CRLF`：追加 `0D 0A`。

新建会话默认选择 `LF`，已有会话保留已保存的设置。终端和分栏视图共用该策略，对文本和 HEX 数据都会生效。

### 5.4 发送历史与周期发送

- 成功发送非空内容后，内容会加入最多 `100` 条的历史记录。
- 连续重复发送同一内容不会重复加入历史。
- 历史下拉框显示最新的条目；选择后回填编辑器，不会自动发送。
- 周期间隔允许 `10 ms` 到 `86,400,000 ms`，默认 `1000 ms`。
- 只有已连接且编辑器非空时才能启动周期发送。
- 周期发送不会重复写入发送历史。
- 断开连接或关闭标签时，周期发送会停止。

### 5.5 使用 Ymodem 发送文件

连接串口后，在左侧“Ymodem 发送”分组中：

1. 点击“…”选择要发送的文件；路径框只读，完整路径显示在悬浮提示中，文件大小显示在指标行。
2. 选择数据块大小：默认勾选“1K 块”（1024 字节）；接收端只支持 128 字节块时取消勾选。
3. 让设备进入 Ymodem 接收模式（部分设备需要复位或按下升级键）。
4. 点击“发送文件”。程序等待接收端发送 `C`，随后发送文件名和大小，再逐块传输并显示进度。

传输期间：

- “发送文件”、文件选择、块大小和 DTR/RTS 被禁用，手动发送和周期发送暂停；终端视图中的回车提交也不会发送。
- 状态文本依次显示“等待接收端 C…”、“发送中”、“完成中…”；指标显示块号、百分比、速度和重试次数。
- 点击“取消”后按钮显示“正在取消…”，程序在安全点向接收端发送 CAN 取消序列并结束本次传输。
- 协议帧不会出现在接收区或日志中；接收区只追加“开始发送文件”“Ymodem 发送完成/失败/已取消”等系统记录。

参数与兼容性：

- Ymodem 要求 8 数据位、无校验，且不要启用 XON/XOFF 流控；不满足时程序会拒绝发送并提示调整参数后重新连接。
- 文件头固定为 128 字节，文件名会转换为 ASCII（非 ASCII 字符丢弃，空格和特殊字符替换为 `_`，保留扩展名）；文件名过长时请重命名。
- 默认数据块为 1024 字节；部分 bootloader 只接受 128 字节块，此时取消勾选“1K 块”。
- 空文件允许发送，只会发送文件头和结束帧；部分接收端可能不接受。
- 传输失败（等待 `C` 超时、重试耗尽、接收端取消、文件读取失败等）不会断开串口，可以修正后重新发送；串口本身发生 I/O 错误时仍会按正常错误流程断开。
- 断开连接、关闭标签或退出程序会中止正在进行的传输。

## 6. 自动日志与导出

日志设置位于左侧设置面板下半部分，内容自上而下排列、不拉伸填满侧栏。“自动保存”与格式下拉框同排且相邻，格式对自动日志和导出都生效；下面一行是“目录”和路径输入框，输入框右侧的“…”按钮用于选择目录；再下面一行是“打开目录”和“导出当前缓冲”，导出按钮更宽，因此在侧栏最窄宽度下按钮也不会被裁切。状态行只在有日志或导出结果时出现，没有内容时自动收起，不占用侧栏高度。自动日志只能在没有连接时修改；修改后的设置用于下一次连接。

### 6.1 自动日志

- 可选择 `CSV` 或 `TXT`。
- 默认目录是当前用户主目录下的 `Documents/SerialMNT/Logs`，也可以手动选择其他目录。
- 每次成功建立连接后创建新文件；断开时刷新并关闭。
- 文件名格式为 `SerialMNT_端口名_YYYYMMDD_HHMMSS.扩展名`。端口名中的非法文件名字符会替换为下划线，重名时追加序号。
- 日志写入失败时会在界面报错，但不会主动中断串口收发。

CSV 使用 UTF-8 BOM，字段顺序为：

| 字段 | 含义 |
|---|---|
| `timestamp` | 本地时间，精确到毫秒并包含时区偏移 |
| `direction` | `RX`、`TX` 或 `SYSTEM` |
| `encoding` | 记录使用的文本编码 |
| `text` | 按指定编码得到的文本 |
| `hex` | 原始字节的大写 HEX 文本 |

TXT 使用 UTF-8，每行格式为：

```text
[本地时间] 方向 [编码] 文本
```

文本无法表示原始字节时，HEX 字段或 HEX 显示模式仍可用于核对数据。

### 6.2 导出当前缓冲

“导出当前缓冲”把当前标签内存中的全部记录写入所选路径，文件格式取当前日志格式下拉框。导出不会清空缓冲，也不会停止自动日志。

## 7. 配置、退出与恢复

### 7.1 配置位置

Windows 默认路径：

```text
%APPDATA%\SerialMNT\settings.json
```

Linux 默认路径：

```text
${XDG_CONFIG_HOME:-$HOME/.config}/SerialMNT/settings.json
```

配置使用版本化 JSON，保存主题、窗口布局、活动标签、串口参数、显示偏好、日志偏好、发送格式、换行、周期间隔、发送历史和视图模式。旧版配置缺少视图模式时按分栏视图恢复。

### 7.2 写入与损坏恢复

- 配置变更后延迟约 `500 ms` 合并写入，关闭程序时立即刷新。
- 写入采用临时文件替换；已有配置会保留为同目录的 `.bak` 文件。
- 配置损坏或版本不受支持时，程序把原文件复制为 `settings.corrupt.<UTC时间>.json`，随后按无配置状态启动。
- 单个标签配置无效时会跳过该标签；其他有效标签仍可恢复。
- 启动恢复只还原参数，不会自动连接或占用端口。

### 7.3 关闭程序

关闭仍有活动连接的会话时，程序会要求确认。退出时所有会话被强制关闭，自动日志刷新后写入磁盘。

## 8. 常见问题

### 端口列表为空

1. 检查 USB 转串口设备驱动和设备管理器。
2. 点端口框右侧的 ⟳ 按钮立即重新枚举，或等待最多 30 秒自动刷新。
3. Linux 下确认设备节点存在，例如 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。

### 连接失败并提示端口被占用

关闭其他串口工具，并检查本应用其他标签是否已经连接同一端口。修改参数后必须断开并重新连接才会生效。

### Linux 提示权限不足

确认当前用户能够访问对应设备节点。常见做法是把用户加入 `dialout` 或发行版对应的串口用户组，然后重新登录。不要长期使用 `chmod 777` 放宽设备权限。

### 中文显示乱码

界面默认按 `UTF-8` 解码；可在“串口设置”的“编码”下拉框切到 `GB18030` 或 `ASCII`，改完需断开并重新连接。也可改用 HEX 模式确认原始字节，并检查设备实际编码和分行边界。

### 日志文件未生成

确认“自动保存”已启用、目录可写且磁盘空间充足。自动日志只在建立了新连接后开始，修改设置不会为已经连接的会话补建日志。

### 配置被重置

检查配置目录是否存在 `settings.corrupt.*.json`。程序读取失败时会保留损坏文件并重新创建配置；可从 `.bak` 恢复上一次成功保存的内容。

### 检查更新失败

确认当前网络可以访问 `api.github.com`。网络不可用、GitHub 限流或尚无正式 Release 时，启动检查会静默跳过，手动检查会在状态栏提示“检查更新失败，请检查网络后重试”。该提示不影响串口收发。

## 9. 已知限制

- 仅支持 Ymodem 单文件发送；不支持 Ymodem 接收、批量/目录传输、断点续传，以及 XMODEM、ZMODEM 等其他文件传输协议。
- 不支持日志回放、脚本、Modbus 或协议插件。
- 不提供自动下载或自动替换式更新；启动更新检查只提示新版本并打开下载页，代码签名、遥测和崩溃上报仍不提供。
- 暂停按钮只暂停界面，不会暂停串口读取、缓冲或日志。
- 终端仿真支持 16 色与 256 色，不支持真彩、alternate screen、滚动区域和 OSC 标题；终端滚动历史上限 5000 行，画面只渲染最近 2000 行。
- Windows 和 Linux 单文件必须分别在对应操作系统上构建。
- 单文件程序未包含自动下载或自动替换式更新；更新检查仅打开 GitHub Release 页面，下载后应核对 SHA-256。
